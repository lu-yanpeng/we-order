# core/session — 会话唯一读写者（Story 1.3）

静默登录、会话持久化、单飞续期、到期前主动续期与失败回退重登全部封在本目录内。
页面 / Composable 不可见，只能经 `api/auth.ts` 门面的 `warmUpSession()` 与
`getSessionUser()` 接触；传输侧经装载时注册的 provider 取凭证与会合（见
`core/transport/README.md`）。「未登录」不是对外状态：要么会合成功，要么以 `AppError` 失败。

## 文件

| 文件              | 职责                                                                            |
| ----------------- | ------------------------------------------------------------------------------- |
| `index.ts`        | 组装 + 向 `core/transport` 注册 provider；对外出口（只允许 `api/` 引用）        |
| `session.ts`      | 状态机：单飞、主动续期、回退重登、退避与上限、凭证变更通知                      |
| `storage.ts`      | `weorder_session` 的**唯一**读写点；形状校验与损坏自愈                          |
| `login.ts`        | `uni.login` 取一次性凭证 → `wechat-login` 换会话；平台 token 端点续期（裸通道） |
| `types.ts`        | 内部形状：`PlatformSession`（平台响应）与 `Session`（持久化形状）               |
| `session.test.ts` | 16 项状态机单测（假 http + stub 存储 + fake timers）                            |

## 对外接口

| 能力                    | 用途                                                                                                |
| ----------------------- | --------------------------------------------------------------------------------------------------- |
| `ensureSession(force?)` | 会合语义：已有有效会话直接复用；续期 / 登录在飞时等待并复用结果；`force` 用于服务端拒绝后的强制恢复 |
| `getAccessToken()`      | 取当前访问凭证（只给 transport 的请求头构造）                                                       |
| `getUserId()`           | 取当前会话主体 id（只给 `api/` 与 `core/realtime`）                                                 |
| `subscribeSession(cb)`  | 凭证变更通知：登录 / 续期成功后回调 `{ accessToken, userId }`（Epic 5 同步订阅凭证用）              |

## 关键行为

- **静默登录**：`uni.login` 一次性凭证 → `wechat-login`（服务端换 openid 并建立会话）；
  无登录界面、无授权弹窗、不索取用户资料。
- **持久化**：`weorder_session` 形状与 Phase 2 完全一致（`accessToken` / `refreshToken` /
  `expiresAt` / `userId`），升级不强制重登；损坏或缺字段按无会话处理并清掉。
- **单飞**：同一时刻只有一条「取有效会话」链在飞（模块内 `inflight`），并发调用等待并复用
  同一结果；续期与回退重登也在同一条链上。
- **主动续期**：每次拿到会话后按 `expiresAt − 5 分钟` 排一个定时器，到点后台续期；失败
  静默且不重排（避免循环），下一次会合时再试。请求前的 `ensureSession()` 是兜底。
- **回退重登**：续期被平台明确拒绝（400 / 401：凭证已失效或被轮换）→ 清本地会话 → 重新
  静默登录；结果不明的网络类失败保留原会话、错误上抛，不用登录掩盖网络问题。
  应用被杀导致新凭证丢失时，下次启动用旧凭证续期被拒，自然走同一条回退路径。
- **退避与上限**：登录失败仅对 `session_failed` / `identity_failed` / `network_unreachable` /
  `timeout` 自动重试，上限 3 次、退避 0 / 1s / 2s；`rate_limited` 等不自动重试。
- **不留半登录**：只有拿到完整会话才写内存与存储；任何失败都不落盘。
- **会话状态**：住在内存（运行时状态的唯一出处），启动时从存储恢复；不在 Pinia、不经
  `api/` 暴露。开发者工具里直接改 Storage 需要重新编译 / 重启才生效。

参数常量集中在 `session.ts` 顶部（`RENEW_LEAD_SECONDS`、`LOGIN_MAX_ATTEMPTS`、
`LOGIN_BACKOFF_MS` 与两个可重试集合）。

## 手动验证（模拟器 / 真机）

前置：本地栈在跑（`supabase start`）、`mp/.env.local` 指向本地栈、开发者工具打开
「不校验合法域名」；入口为启动页「身份链路验证（临时页面）」。改完 Storage 后点一次
「编译」重启再继续。

| #   | 操作                                                                                                                                                                                                                                                                        | 预期                                                                                                    |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 1   | 清掉 `weorder_session` → 重启 → 点【会话预热 / 当前身份】                                                                                                                                                                                                                   | 网络面板 **1 次** `wechat-login`；显示本人 id；Storage 出现会话 JSON；无授权弹窗                        |
| 2   | 再点一次【会话预热 / 当前身份】                                                                                                                                                                                                                                             | 无 `wechat-login`、无续期请求；同一 id（已有有效会话直接复用）                                          |
| 3   | 把 `expiresAt` 改成过去的秒数 → 重启，观察网络面板（无需点击）                                                                                                                                                                                                              | 恢复会话时即后台续期（1 次 `token?grant_type=refresh_token`）；点【会话预热】读取成功                   |
| 4   | 清掉 `weorder_session` → 重启 → **直接点**【并发验证 ×3】（不点预热）                                                                                                                                                                                                       | 网络面板只有 **1 次** `wechat-login`（单飞），3 条全部成功且 id 相同                                    |
| 5   | 把 `expiresAt` 改成 `now + 5 分钟 + 10 秒` → 重启，静置约 15 秒不操作                                                                                                                                                                                                       | 无需点击自动出现 1 次续期（主动续期）；存储更新                                                         |
| 6   | 把 `expiresAt` 改成过去的秒数、`refreshToken` 改成无效值 → 重启，观察网络面板（无需点击）                                                                                                                                                                                   | 1 次续期失败（400）→ 自动 1 次 `wechat-login` 成功；点【会话预热】确认 id 不变（不产生第二个身份）      |
| 7   | 修正版（确定性）：① 清会话重启 → 点【会话预热】完成登录（会话 A）→ ② 整段复制 A 的 JSON 留好 → ③ 把 `expiresAt` 改成过去的秒数 → 重启，等约 5 秒（平台把 A 的刷新凭证轮换成新的，存储变为会话 B）→ ④ 粘贴回 A 的 JSON，并把它的 `expiresAt` 也改成过去 → 重启，观察网络面板 | 旧刷新凭证被平台拒绝（400）→ 自动重登；点【会话预热】确认 id 不变（模拟「续期发出后被杀、新凭证丢失」） |
| 8   | `supabase stop` → 清会话 → 重启 → 点【会话预热】                                                                                                                                                                                                                            | 显示 `[network_unreachable] 网络不可用，请检查网络后重试`；无白屏、不崩                                 |
| 9   | `supabase start` → 再点【会话预热】                                                                                                                                                                                                                                         | 重试成功；id 与步骤 1 相同（可重试、不留半登录）                                                        |
| 10  | 把 `weorder_session` 改成非法 JSON → 重启 → 点【会话预热】                                                                                                                                                                                                                  | 旧值被清掉并重新登录，Storage 恢复为合法会话                                                            |
| 11  | 点【失败文案自检】                                                                                                                                                                                                                                                          | 三行文案互不相同、无堆栈 / 密钥 / OpenID 等敏感信息                                                     |

> 续期路径的单飞（并发只发一次续期）由单元测试覆盖：主动续期在页面加载时即完成，手动并发点按很难落在续期窗口内；步骤 4 用冷启动登录路径观察单飞。
> 步骤 6 的真机复验受限：真机重启小程序会断开真机调试、重连耗时长于「启动瞬间续期 / 重登」的观察窗口；该场景在模拟器验证，真机只复验步骤 1、2。
> 改了 Storage 后必须点「编译」重启（会话状态内存持有，不重启不会重新读存储），否则可能观察不到任何请求。
> 步骤 8 的失败文案会在有界重试（约 3 秒）后出现；这是重试上限，不会循环。
> 真机：至少复验步骤 1、2、6（静默登录在真机才算真证据）；本机需保证手机可访问
> Supabase 地址（见 `docs/phase-2/addendum.md` §H 的域名绕过说明）。
