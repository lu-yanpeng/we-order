### 完成内容

#### 1. 新建 `composables/use-home-tabs.ts`

将首页顶栏 Tab 与 swiper 的双向同步逻辑从页面提取到独立 Composable：

- `activeTab` / `swiperIndex` — 页面级 UI 状态
- `onTabChange` / `onSwiperChange` — Tab ↔ swiper 双向同步
- TDesign tabs 受控模式首屏 workaround（先清空再赋值触发重渲染）

遵循 AD-3：页面仅负责组件编排，交互逻辑封装在 Composable 内。

#### 2. 重构 `composables/use-spec-sheet.ts` — 接管表单状态与价格计算

**上移内容**（从 `spec-sheet/index.vue` 迁移）：

| 迁移项 | 类型 | 说明 |
|--------|------|------|
| `selections` | reactive | 各规格组选中值 |
| `count` | ref | 步进器数值 |
| `hasSpecs` | computed | 是否有规格组 |
| `stepperLabel` | computed | 步进器标签文案 |
| `totalPrice` | computed | 最终价格（调用 `utils/price.ts`） |
| `priceLabel` | computed | 价格旁摘要文案 |

| `updateCount` | function | 步进器 +/- |

| `initSelections` | function | 重置为默认值 |
| `watch(visible → initSelections)` | — | 弹窗打开时自动重置 |

**改动**：
- `confirm()` 不再接收 payload，改为直接读取内部 `selections` 和 `count`
- 导入 `calcTotalPrice` / `buildSpecSummary` 从 `utils/price`（composable → utils，AD-2 ✓）

#### 3. 新建 `utils/price.ts` — `calcTotalPrice()` 纯函数

将原组件内嵌的价格计算规则提取为纯函数，封装领域知识：

```ts
// 浓缩份数 > 1 时，每额外一份 +¥4
if (shotCount > 1) {
  price += (shotCount - 1) * 4
}
```

- 无规格：基础价 × 数量
- 有规格：基础价 + 规格加价（`calcSpecExtras`） + 浓缩加价

#### 4. 精简 `spec-sheet/index.vue` — 退化为纯展示层

**删除**：
- `selections` reactive / `count` ref / 所有 `computed` / `watch`（除 `popupVisible` 桥接和 `safeBottom` 布局）
- `import { calcSpecExtras, buildSpecSummary } from '@/utils/price'`（AD-2：组件不依赖 utils）

**新增 props**：`selections`、`count`、`totalPrice`、`priceLabel`、`stepperLabel`、`hasSpecs`

**新增 emits**：`toggle-option(groupId, optionId)`、`update-count(delta)`

**保留**：
- `popupVisible` computed — t-popup 的 v-model 桥接（UI 适配器，非业务逻辑）
- `safeBottom` ref — 安全区布局计算（纯 UI）
- `isActive` 函数 — 基于 props.selections 的纯显示判断，不涉及业务规则
- `handleClose` / `handleConfirm` — 事件上抛

模板中 `@click` 改为 `$emit('toggle-option', ...)` / `$emit('update-count', ...)`，`{{ count }}` 等从 props 读取。

#### 5. 更新 `pages/home/index.vue`

- 单次调用 `useSpecSheet()`，解构全部字段（之前遗漏导致重复实例化）
- `<spec-sheet>` 新增 6 个 prop 绑定 + 2 个事件绑定
- `handleSpecConfirm` 页面内定义已移除，模板直接绑定 `confirmSpecSheet`

### 其他讨论与结论

#### Composable 目录归属

**结论**：保持 `@/composables/` 扁平结构，不模仿 AD-5 的 "页面内优先" 策略。

**理由**：
- antfu-skills 隐含的 composable 组织方式是按功能域（feature），非按页面归属
- Composable 无模板/CSS，复用成本为零，不会造成目录膨胀假象
- 后续必然出现跨页面 composable（如 `useCart`），两种 import 路径风格会增加认知负担

#### 测试方案

- uniapp 未官方推荐特定测试框架
- 项目 `vite@5.2.8`，可用 `vitest@^2.1` 作纯逻辑测试
- Phase 1 仅有 `utils/price.ts` 值得单元测试，整体暂不引入测试基础设施
- 建议 Phase 3 对接真实 API 时再引入，届时 `api/` 层和 `utils/` 受益更明显
