#### 2. 修改 `utils/price.ts` — 计费模型从"浓缩份数"改为"数量×单价"

**原逻辑**：浓缩份数 > 1 时每额外一份 +¥4；无规格时为基础价 × 数量
**新逻辑**：有规格时单价 = 基础价 + 规格加价，无规格时单价 = 基础价；最终价 = 单价 × 数量（step 步进器统一为购买数量）

- `calcTotalPrice()`：移除浓缩加价分支，改为 `unitPrice * count`
- `buildSpecSummary()`：移除 `shotCount` 参数，不再追加"×份浓缩"后缀

#### 3. 修改 `composables/use-spec-sheet.ts` — 步进器统一为"数量"

- `stepperLabel`：从 `'浓缩份数' | '数量'` 改为固定 `'数量'`
- 新增 `unitPrice` computed：有规格 = 基础价 + 规格加价，无规格 = 基础价
- 新增 `specSummary` computed：纯规格摘要（不含数量），供 CartItem 存储
- `priceLabel`：有规格时 = `"规格摘要 x数量"`，无规格时 = `"x数量"`
- `confirm()`：简化为仅关闭弹窗，购物车写入由页面编排

#### 4. 新建 `api/cart.ts` — localStorage 持久化

遵循 AD-1：外部数据源读写经由 API 层。

#### 5. 新建 `stores/cart.ts` — Pinia 购物车 Store

遵循 AD-6（跨组件共享状态）、AD-8（单一写入口）。

### 遇到的问题与修复

#### 问题 1：pinia@4 与微信小程序构建不兼容

**现象**：`pnpm build:mp-weixin` 报错 `Could not resolve "nostics"`

**根因**：`pinia@4.0.2` 新增依赖 `nostics`（Vercel 诊断库），与 uniapp Vite 微信小程序构建管线不兼容。
uniapp 官方文档建议 CLI 4.14 后可不指定 pinia 版本，但文档编写时 pinia 最新版为 v2.x。

**修复**：锁定 `pinia@2.3.1`（同大版本最新稳定版，无 nostics 依赖）。

#### 问题 2：结算栏不更新（storeToRefs）

**现象**：加入购物袋后 localStorage 有数据，但 checkout-bar 始终显示 0。

**根因**：Pinia setup store 中 `store.totalCount` 返回的是**值快照**（number），不是 ComputedRef。
`useCart()` 返回这些快照值后，模板拿到的是一次性静态值，后续 store 变化不触发更新。

**修复**：使用 `storeToRefs(store)` 提取原始 ComputedRef，保持响应式链路。

#### 问题 3：加料选择顺序不同导致 SKU 错误分叉

**现象**：同一商品、相同加料，仅选择顺序不同（先奶油后焦糖 vs 先焦糖后奶油），被判定为不同 SKU。

**根因**：`selectionsKey()` 只排序了顶层 key（`size, temp, milk...`），多选组的数组值未排序。

**修复**：`selectionsKey()` 序列化前对数组值执行 `[...val].sort()`，确保同一组合产生相同 key。
