# 产品简报：We-Order 星巴克点餐小程序

## 核心摘要 (Executive Summary)

We-Order 是一款借鉴星巴克 UI 设计规范的原创点餐小程序（UI 界面通过 Open Design 独立设计完成）。本项目旨在作为高质量的前端求职作品集，全方位展示候选人在工程架构、高保真还原度以及全栈视角的综合能力，使开发者能 100% 聚焦于前端交互的丝滑体验和代码的工程化质量。

## 背景与技术策略 (Background and Tech Strategy)

在以展示前端实力为目标的个人练手项目中，开发者往往面临“无米之炊”的困境：不写后端无法跑通真实业务，而强行手写后端则易陷入技术泥潭。由于上一个版本采用手写 FastAPI 导致后端架构腐化并成为项目瓶颈，本项目决定**拥抱 BaaS，拒绝内耗**。

引入 **Supabase** 作为后端基础设施。借助 Supabase 提供的“开箱即用”的数据库、身份验证和 API 服务，可大幅减少传统后端接口的开发量。剩余必要的接口逻辑（如匿名登录）将借助 AI 与 Supabase 完善的文档来高效补全。前端则采用 **Uniapp + Vue + TypeScript + TailwindCSS** 的现代技术栈。我们不盲目堆砌功能或“炫技”，而是专注于“1:1 真实还原”现有的高保真 HTML 原型，以“完成度”和“严谨性”作为项目最大的优势名片。

## 受众与成功指标 (Audience and Success Criteria)

**目标受众**：首要受众为技术面试官、前端技术主管和 HR；次要受众为开发者本人。受众看重的是代码的整洁度（TypeScript 的严谨性）、技术选型的合理性，以及能否独立完成一个复杂的业务闭环。

基于受众诉求，本项目的**成功指标**设定为：
- **核心流程跑通**：用户可以顺利完成从匿名登录、浏览商品、加购到模拟下单的全流程。
- **原型 1:1 还原**：UX 和 UI 表现与已有的 HTML 原型（Open Design 设计产物）保持高度一致，不做画蛇添足的魔改。

## 项目范围 (Scope)

**包含 (In Scope):**
- 微信小程序端（基于 Uniapp）：
  - 微信静默授权登录（仅通过 **OpenID** 匿名关联用户订单，不获取任何其他隐私信息）。
  - 商品列表展示与分类切换。
  - 商品详情与规格选择（如冰度、糖度、杯型）。
  - 购物车管理与本地状态维护。
  - 提交订单与历史订单状态查看。
- 后端服务（基于 Supabase）：
  - 基础表结构设计（如：商品表、订单表、用户表）。
  - 接口调用及数据存储。初期直接通过 Supabase 控制台进行基础商品数据的增删改查。

**暂缓 / 排除在外 (Out of Scope):**
- B端后台管理系统（Vben Admin）：暂缓开发，直到小程序端和后端联调全部完工后，视情况与余力再进行开发。
- 真实的微信支付对接（使用前端模拟交互替代）。
- 复杂的用户个人中心管理（积分、卡券、真实手机号绑定等）。

## 演进愿景 (Vision)

如果此版本按期大获成功，它将成为一份无可挑剔的“高含金量简历项目”。在小程序端完全跑通之后，项目可以继续演进：补充完整的 B端后台（基于 Vben Admin），实现从商家上架商品、接单、处理订单到用户端状态实时同步的完整 O2O 闭环系统。
